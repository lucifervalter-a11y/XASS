# XASS iOS

XASS 0.21 — приложение для iOS/iPadOS 17+ на SwiftUI. Встроенных веб-страниц нет: WebContainer удалён, вход выполняется через нативную привязку. Для всех новых функций нужны backend и Windows-агент версии 0.21.0.

Пять вкладок: **Главная, Музыка, Сайт, Инструменты, Погода**. На главной — состояние сервера и устройств; в разделе сайта — формы профиля, проектов, цвета и виджетов. Инструменты открывают устройства, загрузки, уведомления, диагностику, сценарии, правила, историю событий и архив переписок. Музыка использует AVPlayer, включая фон, экран блокировки, AirPlay и локальные загрузки.

## Первый вход

1. В XASS Mini App в Telegram откройте `Инструменты → iPhone и веб-приложение` и создайте свежую одноразовую ссылку.
2. В приложении вставьте полную ссылку в поле ключа или адреса. Для ссылки отдельный адрес вводить не нужно.
3. Подтвердите привязку через Face ID или код-пароль. Ключ устройства остаётся в Secure Enclave, сессия — в Keychain.
4. При повторном запуске достаточно системной разблокировки. Если сессия истекла, приложение предложит новую нативную привязку.

Для зашифрованных снимков и файлов ранее привязанного ПК импортируйте существующий защищённый файл ключа XASS в рабочих инструментах. Нативная привязка iPhone и ключ шифрования файлов решают разные задачи; приложение не заменяет ключи старых ПК автоматически.

## Сборка

На Mac с Xcode и выбранными command-line tools:

```sh
brew install xcodegen
bash ios/prepare.sh
open ios/XASS.xcodeproj
```

Выберите свой Team и bundle identifier для установки на устройство. CI `Build XASS iOS (unsigned)` запускает unit tests в симуляторе и собирает arm64 `.ipa` без подписи. Артефакт `XASS-iOS-UNSIGNED-requires-signing` содержит инструкцию и SHA-256. Подробнее: [UNSIGNED.md](UNSIGNED.md).

## Границы безопасности

- Для управления ПК привяжите нативный ключ свежей одноразовой ссылкой из Telegram Mini App. Аппаратный P-256 ключ подписывает точный одноразовый challenge с назначением, устройством и параметрами команды; закрытый ключ не покидает iPhone. Подпись требует системной биометрии или кода. Отмена не отправляет команду. Старая веб-cookie сама по себе не разрешает регистрацию нового ключа.
- Переключение воспроизведения ожидает остановки предыдущего плеера и сохраняет позицию. Удалённое управление iPhone требует работающего приложения; inbox не является push-сервисом пробуждения iOS. Устаревшие команды не исполняются после возвращения через долгое время.

- Настраивается только HTTPS origin, без userinfo. Экраны обращаются к OwnerAPI напрямую. Транспорт ограничивает пути, размер ответа и запрещает перенаправление запросов с cookie.
- Origin и HttpOnly owner-cookie сохраняются в Keychain `AfterFirstUnlockThisDeviceOnly`. Одноразовая ссылка не записывается на диск. При выходе также очищаются website data, оставшиеся от старой версии.
- Face ID **или системный код-пароль** требуется при возвращении в приложение. При сворачивании window-level privacy shield закрывает также sheets. Музыка не останавливается.
- Native stream использует AVAssetResourceLoader и URLSession с проверкой каждого redirect; ticket не уйдёт на другой origin. Не используются ATS/TLS bypass или произвольные заголовки из JS.
- Загрузки находятся в sandbox Application Support, исключены из iCloud backup и защищены iOS FileProtection. Индекс содержит название/исполнителя, но не URL/ticket. Разные серверы имеют отдельные namespaces. Максимум 256 МиБ на трек. Ручные загрузки выполняет системная фоновая URLSession; очередь сохраняется между запусками, доступны пауза, продолжение и отмена.
- «Удалить локальную копию» не удаляет трек на сервере. «Отключить сервер» сохраняет оффлайн-файлы; вернувшись к тому же origin и разблокировав приложение, можно снова их слушать.
- Звуковые форматы зависят от AVFoundation. Предпочтительны MP3/M4A/WAV; наличие FLAC/OGG в серверной библиотеке не гарантирует воспроизведение каждого кодека на iOS.

## Часто слушаемое и ручные загрузки

Автоматический кэш по умолчанию ограничен 256 МиБ. После второго фактического запуска трек может быть сохранён для повторного прослушивания; при заполнении удаляются наиболее давно использованные автоматические копии. В настройках можно отключить кэш или выбрать 256, 512 либо 1024 МиБ. Кэш изолирован по серверу, защищён FileProtection и исключён из резервной копии iCloud.

Ручные загрузки хранятся отдельно: автоматическая очистка их не затрагивает. Сохранение уже закэшированного трека вручную не требует повторного скачивания. Серверные оригиналы и копии на агенте не удаляются автоматически. Автоматический кэш по-прежнему заполняется, пока приложение или аудиосессия работают; системная фоновая очередь используется для явно запрошенных ручных загрузок.

## Фоновая очередь ручных загрузок

`BackgroundDownloads` восстанавливает задачи одной постоянной `URLSessionConfiguration.background` через `getAllTasks` и UIApplicationDelegate. Одновременно запускаются не более двух файлов; очередь ограничена 100 записями. Метаданные сохраняются атомарно, URL с билетом и `resumeData` — в Keychain `AfterFirstUnlockThisDeviceOnly`. В диагностические события эти значения не попадают. Полученный файл проверяется по origin, track path, MIME, размеру и полной длине ответа перед добавлением в медиатеку. Промежуточная копия сохраняется до записи индекса, чтобы завершить сохранение после перезапуска.

URLSession сама пережидает временную потерю сети. При ручной паузе сохраняется доступная `resumeData`. Срок ссылки берётся из серверного `expires_in` (сейчас один час), проверяется и сохраняется вместе со ссылкой в Keychain; старые записи без срока используют прежний предел 15 минут. Валидная часовая ссылка позволяет продолжить после 20-минутной паузы без сброса сохранённого среза. Возобновление с прежнего байта зависит от сервера и действительности билета: при истёкшем билете запрашивается новая ссылка и файл скачивается заново, содержимое `resumeData` не переписывается. Отмена, пауза, выход и новый запрос ссылки делают запоздавшие ответы прежнего запроса недействительными. Принудительное закрытие приложения пользователем может отменить системные передачи; очередь остаётся доступна после следующего запуска. Выход отзывает локально сохранённые ссылки и останавливает очередь; уже скачанная музыка остаётся.

Отличие фонового транспорта: iOS сама обрабатывает redirects и не вызывает foreground redirect-delegate. Поэтому в фоновые задачи не передаются owner-cookie, API-ключи, Authorization или URL credentials; разрешён только исходный проверенный URL конкретного трека, а результат с чужого origin отклоняется. Это проверка результата, а не обещание блокировать сам сетевой redirect. Серверный stream endpoint должен отдавать аудио напрямую без перенаправлений. Потоковое воспроизведение и автоматический кэш сохраняют прежний foreground транспорт с проверкой каждого redirect.

Очередь и проверки ответов покрыты `BackgroundDownloadTests`. Системное завершение приложения, блокировка физического iPhone, смена Wi-Fi/LTE и восстановление `resumeData` требуют отдельной проверки на устройстве; один успешный XCTest этого не доказывает.

## Надёжность воспроизведения

- Запуск на iPhone сначала получает разрешённую сервером музыкальную сессию; отказ сервера не маскируется успешным запуском.
- При передаче на ПК прежний источник останавливается и подтверждает передачу. Старый heartbeat ПК не считается подтверждением тишины после новой команды воспроизведения.
- Отмена работает и во время первого запроса передачи. Зависшие передачи истекают при обычном опросе, не оставляя музыку заблокированной.
- Поиск не применяет устаревшие ответы, текущий трек сохраняет метаданные при смене фильтра, плейлисты загружают все страницы.
- Мини-плеер располагается внутри области содержимого вкладки и не перекрывает нижнюю навигацию.

## Расшифровка на iPhone

В информации о песне откройте «Другой способ: расшифровать на iPhone». Распознаётся уже скачанный файл, без микрофона. По умолчанию нужна локальная модель языка. Только явное включение переключателя разрешает распознавание Apple через интернет при отсутствии локальной модели; если локальная модель есть, используется она. В режиме Apple через интернет аудио может отправляться в Apple.

Ошибки отдельных 45-секундных фрагментов теперь дают **частичную расшифровку**: рядом с текстом указаны число нераспознанных фрагментов и интервалы пропусков. Успешные фрагменты сохраняют исходные таймкоды. Ошибка не считается доказательством отсутствия вокала; пропуски нужно проверить и дополнить либо повторить распознавание. Предупреждение остаётся рядом с редактируемым текстом до сохранения или получения нового результата. Сохранение по-прежнему выполняется только кнопкой «Сохранить проверенный текст».

Если все фрагменты завершились ошибкой или слов нет, результат не публикуется как готовый. Отмена не превращается в частичный успех. Сообщения различают локальное распознавание и разрешённый режим Apple через интернет; в последнем нет утверждения, что аудио не отправлялось в облако. Настройки доступа, выбор режима и отправка аудио не изменены.

`NativeTranscriptTests` проверяет частичный результат, интервалы и таймкоды, полный сбой в обоих режимах, отмену, пустой текст и ограничения размера. Для выполнения этих XCTest нужны macOS/Xcode и iOS Simulator; проверки исходников на Windows не заменяют их и не подтверждают сборку IPA.

## Проверка и ограничения

GitHub Actions выполняет XCTest и UI-тесты на macOS, сохраняет журнал, результат XCTest, снимки реальных SwiftUI-экранов с тестовыми данными и unsigned IPA. Ветки `codex/**` создают проверочные артефакты; публичный release обновляется только из `main` после успешных проверок.

Secure Enclave, Face ID, физические аудиомаршруты, работа после блокировки настоящего iPhone и реальная пара iPhone–Windows требуют проверки на устройствах. Симулятор не подтверждает эти аппаратные сценарии. Автоматической гарантии запуска на спящем чужом iPhone нет: без активной аудиосессии iOS может приостановить приложение.

Файловые инструменты ПК позволяют открыть папку, скачать файл для просмотра, загрузить файл через системный выбор и удалить выбранный файл после подтверждения. Результат показывается только после ответа агента. Если ПК опубликовал ключ шифрования, загрузки шифруются существующим ключом владельца; без него приложение предлагает импортировать ключ, а не отправляет файл открытым текстом.

Предпросмотр вложений и файлов ограничен 16 МиБ; загрузка на ПК — 16 МиБ с учётом шифрования. Музыкальные загрузки имеют отдельный лимит. Импорт музыки из файлов/ZIP и Telegram реализован; незавершённые ветки VK-импорта не включены. VK остаётся существующим источником now playing, но не новой кнопкой скачивания всей медиатеки.

API references: [AVAudioSession](https://developer.apple.com/documentation/avfaudio/avaudiosession), [AVAssetResourceLoaderDelegate](https://developer.apple.com/documentation/avfoundation/avassetresourceloaderdelegate), [LocalAuthentication](https://developer.apple.com/documentation/localauthentication/lapolicy/deviceownerauthentication).

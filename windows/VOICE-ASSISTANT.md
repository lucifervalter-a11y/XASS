# Локальный голосовой помощник XASS — MVP

Добавлена страница **Помощник** в существующую оболочку WinUI 3. Она работает
без сервера XASS и без подключения к аккаунтам. Текстовый режим не требует модели.
Запись запускается только кнопкой, длится 6 секунд и заканчивается до распознавания.
Аудио обрабатывается в памяти и не записывается в файл. Фоновое прослушивание,
wake word и автозапуск отсутствуют.

## Запуск на этом ПК

Из корня этой рабочей копии:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows\Start-VoiceAssistant.ps1
```

Скрипт открывает уже собранный `artifacts/windows-native/Xass.Native.exe`,
подставляет существующий Python `%LOCALAPPDATA%\XASS\transcription\python\python.exe`
и существующий кэш Whisper small, если они доступны. Ничего не устанавливает.
Откройте **Помощник**. Подключение на странице музыкального агента не требуется.

1. Проверьте настройки. В этой машине TLauncher находится в
   `%APPDATA%\.minecraft\TLauncher.exe`, его настройки —
   `%APPDATA%\.tlauncher\tlauncher-2.0.properties`.
2. Нажмите **Записать 6 секунд**. Дождитесь надписи **Говорите**: загрузка модели
   происходит до открытия микрофона. Используется стандартный микрофон Windows.
3. Проверьте текст и действие. Можно исправить текст и нажать **Разобрать текст**.
4. Нажмите **Выполнить**. Изменение любого поля отменяет ранее подготовленный план.
   Повторное нажатие во время работы не запускает второй процесс.

Кнопка **Отменить** останавливает запись/распознавание либо удаляет подготовленную
команду. Закрытие окна останавливает дочерний процесс помощника. Уже переданное
Windows действие не откатывается. Модель загружается заново для каждой записи;
это проще для контроля микрофона, но даёт несколько секунд подготовки.

## Команды и фактический результат

| Фраза | Действие и граница проверки |
|---|---|
| «Запусти майнкрафт» / «Запусти Minecraft» | Проверяет текущий `forgeai2`, путь игры и Forge 1.20.1; запускает только TLauncher без аргументов. Кнопку запуска игры пользователь нажимает в лаунчере. |
| «Открой ютуб» / «Открой YouTube» | Передаёт Windows фиксированный адрес YouTube. |
| «Открой дискорд» | Передаёт зарегистрированному приложению Discord фиксированный URI. |
| «Перейди к каналу Шаурма классическая» | Открывает страницу по введённой пользователем ссылке канала. Нужна точная ссылка; поиск по аккаунту не выполняется. |
| «Подключись к голосовому каналу Шаурма классическая» | Требует отдельного подтверждения. **В поставленном MVP возвращает blocked: OAuth/RPC-коннектор не настроен.** |

Допустим префикс «Джарвис,». Неизвестные, отрицательные и составные фразы в режиме
точных команд отклоняются. Успешная передача Windows означает `dispatched`,
а не подтверждение загрузки сайта, появления окна или старта Minecraft.

Вход в голос Discord **не реализован как готовая пользовательская интеграция**.
Есть тестируемый `AuthorizedDiscordRpc` для уже авторизованного транспорта:
проверка ID/сервера/имени/типа канала → проверка текущего канала →
`SELECT_VOICE_CHANNEL` с `force=false` → `GET_SELECTED_VOICE_CHANNEL`.
Без подтверждённого результата он не сообщает об успешном подключении.
OAuth-приложение, обмен кодом и разрешённый IPC-транспорт должны быть добавлены
отдельно; поля для user token, selfbot и чтения данных аккаунта отсутствуют.
См. [официальную документацию Discord RPC](https://docs.discord.com/developers/topics/rpc).

## Модели и зависимости

По умолчанию работает `RulePlanner`: это детерминированный разбор поддерживаемых
фраз, **не LLM**. Интерфейс `Planner` позволяет подключать другие провайдеры.
Опциональный `OllamaPlanner` использует только `127.0.0.1:11434/api/chat`,
ограниченный JSON-ответ и имя уже установленной модели. Для него надо отдельно
запустить имеющийся Ollama и выбрать модель в настройках. XASS не запускает
Ollama, не скачивает модели, не покупает API и не принимает API-ключи.
Живой LLM в этой задаче не был доступен; этот адаптер проверен с подставным HTTP.

Whisper работает локально на CPU/int8, 4 потока, модель small, без Demucs/large-v3.
На этом ПК существующая среда с `faster-whisper==1.2.1` и кэш small были пригодны.
При запуске на другом ПК можно подготовить отдельное окружение Python 3.12:

```powershell
py -3.12 -m venv .venv-voice
.\.venv-voice\Scripts\python.exe -m pip install -r pc_client/voice-requirements.txt
```

Укажите абсолютный путь к этому Python и к заранее полученной доверенной локальной
папке модели faster-whisper (с `model.bin`, `config.json`, `tokenizer.json`,
`vocabulary.txt`). Автоматическая загрузка в коде отключена (`local_files_only=True`).
Можно передать эти пути параметрами `-PythonPath` и `-ModelPath` скрипту запуска.
Модель/аудиодрайверы не входят в опубликованную папку приложения.

## Архитектура и расширение

`MainWindow` → `AssistantClient` → одноразовый `assistant_bridge.py` →
`voice_capture` / `Planner` → строгая проверка `Plan` → `LocalExecutor`.
Каждый запрос ограничен по размеру и времени; stdout содержит JSON-состояния.
Пути, URI, параметры shell и подтверждения из ответа модели не принимаются.
Пользователь видит план до действия; для входа в голос дополнительно проверяется
явная исходная фраза, затем отдельное подтверждение.

Существующая цепочка `AgentCommand → heartbeat → CommandExecutor →
_dispatch_agent_command`, музыкальный мост и серверные разрешения сохранены.
В MVP голосовой адаптер намеренно не публикует команды в удалённую очередь:
без проектирования удалённого подтверждения локальный голос не должен расширять
права сервера. Новый слушатель/сетевой агент не создаётся. Для других устройств
следующий этап — транспорт через существующую очередь, при той же схеме действий
и подтверждений; список устройств в этой задаче не определён.

## Сборка и проверки

Обычная сборка с .NET SDK 8 и доступом к NuGet:

```powershell
dotnet publish windows/Xass.Native/Xass.Native.csproj -c Release -r win-x64 -p:RuntimeIdentifiers=win-x64 -p:Platform=x64 -o artifacts/windows-native
python -X utf8 -B -m unittest discover -s windows/tests -v
```

Нужно сохранять всю папку `artifacts/windows-native`, включая PRI, DLL и четыре
Python-файла. Три исправления WinUI из предыдущей задачи сохранены: версия
BuildTools 10.0.26100.4654, `EnableMsixTooling`, выход при закрытии окна.

Проверка микрофона, реальный запуск приложений и вступление в Discord во время
разработки не выполнялись. Тесты заменяют эти побочные эффекты фикстурами.
Проверено реальное распознавание синтетической русской WAV-фразы локальным Whisper;
это проверяет модель, но не качество пользовательского микрофона.
WinUI скомпилирован на Windows; интерактивный визуальный smoke test недоступен
в этой сессии из-за отсутствия рабочего инструмента UI.

# XASS 0.14.0 — проверка перед выпуском

Изменения объединены с 0.13.5: сохранены DPAPI, E2E, Passkey и зашифрованные копии сервера. Рабочий сервер при этой проверке не изменялся.

## Что изменилось

- Windows: честный статус последнего heartbeat, отсутствие ложного «подключён» от `/health`, неблокирующий список процессов, адаптивная навигация и проверка обновления без получения очереди команд.
- Команды ПК: опрос до 5 секунд между запросами при доступной сети, немедленное подтверждение результата, справедливая повторная доставка и защита от повторного выполнения прерванных действий. Продолжительные команды и сеть могут увеличить задержку.
- Mini App / iPhone PWA: читаемые размеры, безопасные зоны экрана, управление с клавиатуры, подтверждение опасных действий, сохранение ссылки входа при ошибке обмена, понятные ошибки шлюза и тайм-ауты. HTML с авторизацией и приватные файлы не кешируются.
- E2E: перенос ключа между Telegram, Safari и PWA через локально зашифрованный `.xass-key` в разделе **Инструменты → iPhone**. Пароль и приватный ключ не отправляются серверу. Это отдельный ключ от Passkey/Face ID и файла подключения агента.
- Файлы: корректная передача русских названий, проверка шифрованного пакета до записи, отсутствие незаметной подмены зашифрованного файла обычным.
- Перенос: **Инструменты → Перенос** — зашифрованная полная копия или одноразовый код; ручной незашифрованный архив вынесен в дополнительную инструкцию. Оба пути проверяют файловые пути и сбрасывают старые команды после восстановления.
- Безопасность: локальные конфиги, резервные копии конфигов, ключи рабочего ПК и виртуальные окружения не включаются в ZIP обновления. Старый маршрут скачивания полного серверного архива требует индивидуального ключа ПК и свежей команды владельца на этот файл.

## Проверки

```powershell
python -m unittest discover -s tests
node --test tests/test_pwa_runtime.js tests/web_runtime.test.cjs tests/e2e_browser.test.cjs
```

Среда проверки: Python 3.12, Node.js; Windows. Криптотесты используют настоящие ECDH / HKDF / AES-GCM и проверяют несовпадение ключа, неверный пароль, повреждение пакета и раздельные назначения шифрования.

В локальном браузерном стенде проверены Chromium (320×740, 390×844, 1280×900) и WebKit (390×844): пять вкладок, переполнение по горизонтали, карточка ПК, подтверждение и отмена блокировки, перенос сервера и ключа. Отдельно проверен вход: ответ 503 → повтор → успешный обмен одноразовой ссылки. Команды и авторизация выполнялись на тестовых данных, не на настоящем ПК.

Windows-интерфейс проверен в изолированном `--preview` без живого конфига и запуска агента. Собран Inno Setup installer; проверены версия PE, содержимое EXE (E2E/DPAPI) и `--health-check`. Установщик не устанавливался поверх пользовательской версии. Локальная сборка помечена `local_build`, это не подписанный публичный релиз.

## Перед публикацией

1. Проверить серверные тесты и PHP/nginx на целевом Linux. В этой Windows-среде активация Linux и восстановление живого PostgreSQL не выполнялись.
2. Пройти реальный сценарий на iPhone: HTTPS → вход → экран «Домой» → Face ID → импорт ключа → снимок/файл своего ПК. WebKit-эмуляция не заменяет настоящий Safari и Telegram WebView.
3. Проверить обновление установленного Windows-агента на тестовом ПК. Для Unicode-передач новый агент следует использовать с обновлённым backend.
4. При миграции сохранить домен и ключи, проверить копию до отключения старого сервера. Подробности: [защищённый перенос](SERVER_MIGRATION.md), [ручной перенос](MIGRATION.md).

Push в `main` включает существующий автоматический деплой. Для проверки без изменения VPS используйте отдельную ветку; не сливайте её до готовности целевого сервера.
